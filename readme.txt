同期パターン（wp_block）を「名前」（見つからなければ「スラッグ」）で取得するヘルパー関数と、テンプレートや投稿に置けるブロックを提供します。

== Description ==

同期パターン（`wp_block` カスタム投稿タイプ）を、投稿 ID ではなく**名前（post_title）**、見つからなければ**スラッグ（post_name）**で引いて表示します。投稿 ID は環境ごとにずれるため（ローカルと本番など）、テンプレートやコードに ID を書くと壊れます。名前やスラッグは環境をまたいでも変わりません。

* **ブロック `gpbpn/pattern`**（1.5.0 で追加）: テンプレート・テンプレートパーツ・投稿本文に置けます。名前またはスラッグを 1 つ指定するだけです。
* **関数 `get_pattern_by_name()` / `get_pattern_by_slug()` / `get_pattern_by_name_or_slug()`**: テーマやプラグインのコードから呼び出せます。

**主な特徴**

* 名前・スラッグとも完全一致検索（部分一致にはなりません）。日本語にも対応
* 名前を優先し、一致するパターンが無いときだけスラッグで探します（ブロックと `get_pattern_by_name_or_slug()`）
* `sanitize_text_field()` による入力のサニタイズ、および文字列以外・極端に長い名前の早期拒否（`gpbpn_max_name_length` フィルタで上限を変更可能。既定 255）
* 同名パターンが複数存在する場合は ID が最も小さい 1 件（最初に作成されたパターン）を返し、重複を `gpbpn_duplicate_pattern_found` アクションで検知可能
* `no_found_rows` およびタクソノミー/メタキャッシュの更新省略による軽量なクエリ
* オブジェクトキャッシュによる解決結果のキャッシュ（パターンの保存・更新・削除時に自動的に無効化されます。負の結果＝見つからなかった場合も含めてキャッシュします）
* `gpbpn_strict_title_match` フィルタで、DB の照合順序（大文字小文字・全角半角を区別しない場合がある）に依存しない厳密なタイトル一致を要求可能。`get_pattern_by_name()` は既定で無効（後方互換のため opt-in）、新しい `get_pattern_by_name_or_slug()` とブロックは既定で有効
* `gpbpn_synced_only` フィルタで、同期パターン（`wp_pattern_sync_status` が未設定/空のもの）のみに限定して取得可能（既定は無効。後方互換のため opt-in）
* 日本語の翻訳を同梱（ブロック名・編集画面の文言）
* wp.org には掲載していないため、GitHub Releases を版元とした自動更新に対応（管理画面での更新通知 → ワンクリック更新）。更新チェックのためのキャッシュ済み HTTP 通信のみ発生し、`l2dwpghul_updater_enabled` フィルタで `false` を返すことで完全に無効化可能

**ブロックの使い方**

ブロックエディターで「パターン（名前またはスラッグ）」ブロックを挿入し、同期パターンを選びます（選ぶと**名前**が保存されます）。サイドバーでは、名前またはスラッグを直接入力することもできます。

テンプレート（`.html`）やテンプレートパーツには、ブロックのマークアップをそのまま書けます。

```html
<!-- wp:gpbpn/pattern {"pattern":"ヘッダーバナー"} /-->
```

* 見つからないとき、フロントには何も出力しません（`gpbpn_pattern_not_found` アクションは発火します）。編集画面には「パターンが見つかりません: {指定した文字列}」と表示します。
* 公開済み（publish）でないパターンやパスワード付きのパターンは表示されません（コアの同期パターンのブロックと同じです）。
* ブロックの選択欄には、同期パターンだけが出ます。同期していないパターン（unsynced）は、挿入するとコアが内容をコピーとして展開するため、このブロックで参照すると意図と違う動きになるためです。入力欄に名前を直接書けば、同期していないパターンも表示できます。
* クエリーループの中に置くと、`postId` などの文脈が中のブロックに渡ります。
* パターンの上書き（pattern overrides）には対応していません。パターンの初期の内容で表示されます。
* 自分自身を含むパターンは、コアの仕組みで無限ループを防ぎます。

**名前とスラッグ**

* 名前（`post_title`）は、管理画面の「パターン」一覧に表示されるタイトルです。**管理画面ではパターンのスラッグを確認・編集できません**（`wp_block` は公開されない投稿タイプのため、スラッグ欄が出ません）。スラッグはブロックのサイドバー（「スラッグ:」）で確認できます。
* 名前は後から変更できますが、スラッグは作成時の名前から作られたまま残ります。名前を変えても壊したくない指定には、スラッグを使います。サイドバーの「スラッグで指定する」ボタンで、指定をスラッグに切り替えられます。
* 名前を変えても、作成時の名前のまま書いておけば、スラッグ側で見つかることが多いです（名前から作られたスラッグと一致するため）。ただし、同名のパターンがあって `-2` などが付いた場合や、作成時と違う名前で書いている場合は見つかりません。
* **日本語のスラッグは 22 文字程度まで（エンコード後 200 バイトの上限）。絵文字などを含むと 16 文字程度まで**です。WordPress が作成時にスラッグを 200 バイトに切り詰めます。長い名前のパターンをスラッグで指定したいときは、**作成時の名前を英数字にしてください**（例: `discover-alpine-intro`）。作成後に日本語の名前へ変えても、スラッグは作成時のまま残ります。
* スラッグで探すときも、WordPress の正規化（`sanitize_title_for_query()`）が値を 200 バイトに切り詰めます。長すぎる入力は、切り詰めた値で照合されます（WordPress 本体の URL 解決と同じ挙動です）。
* **名前が別のパターンのスラッグと一致する場合は、名前が優先されます。** たとえば、テンプレートにスラッグ `discover-alpine-intro` を書いていても、だれかが名前を `discover-alpine-intro` にした別のパターンを作ると、そちらが表示されます（パターンを作れるのは編集者以上です）。ブロックのサイドバーには、この状態の注意を表示します。

**環境間の移行（ローカル → 本番など）**

名前優先なので、本番でも同じ名前でパターンを作れば表示されます。スラッグで指定している場合は、スラッグが環境間で揃っている必要があります。スラッグは名前から自動で作られるため、同名のパターンが先にあると `-2` が付いてずれます。次の方法で移行できます（実測済みの内容です）。

* **ツール > エクスポート（WXR）と WordPress Importer**: スラッグ（`post_name`）が引き継がれます。
* **WP-CLI**: `wp post update {ID} --post_name={スラッグ}` でスラッグを直せます。
* **パターンの JSON エクスポート / インポート**: JSON にスラッグは含まれず、インポートでは名前からスラッグが作られます。同名のパターンが既にあると、新しい方のスラッグに `-2` が付きます（この場合も `get_pattern_by_name_or_slug()` は、元のパターン＝ID の小さい方を返します）。

**関数の使い方**

```php
// 名前で取得する（1.0.0 から。挙動は変わりません）.
$pattern = get_pattern_by_name( 'ヘッダーバナー' );

// スラッグで取得する（1.5.0 から）. 日本語は URL エンコード済み・デコード済み・大文字のどれでも一致します.
$pattern = get_pattern_by_slug( 'header-banner' );

// 名前で探し、見つからなければスラッグで探す（1.5.0 から. ブロックはこの関数を使います）.
$pattern = get_pattern_by_name_or_slug( 'ヘッダーバナー' );

if ( $pattern ) {
    echo apply_filters( 'the_content', $pattern->post_content );
}
```

| 関数 | 探す対象 | `gpbpn_strict_title_match` の既定 | `gpbpn_max_name_length` |
| --- | --- | --- | --- |
| `get_pattern_by_name()` | 名前 | 無効（1.4.0 までと同じ） | 適用 |
| `get_pattern_by_slug()` | スラッグ | 適用しない | 適用しない |
| `get_pattern_by_name_or_slug()` | 名前 → スラッグ | 名前に対して有効 | 適用（名前の段階で超過すれば null） |

**フック**

外部から挙動を拡張するための 8 つのフック（`gpbpn_` 接頭辞）を提供します。1.5.0 からは、名前だけでなくスラッグで探すときにも同じフックが呼ばれ、最後の引数に `$field`（`'title'`・`'slug'`、`get_pattern_by_name_or_slug()` の結果では `'name_or_slug'`）が渡ります。`add_filter()` / `add_action()` は受け取る引数の数を登録時に指定するので、既存のコールバックには従来どおりの引数だけが渡ります。ただし、**既存のコールバックは、スラッグで探すときにも呼ばれます**（その場合、第 2 引数にはスラッグが渡ります）。名前のときだけ処理したい場合は、`$field` を受け取って判定してください。

* `gpbpn_pre_get_pattern`（filter）— クエリ発行前の短絡。外部のキャッシュ層や transient によるクエリ回避に使用できます（1.3.0 以降、内部でもオブジェクトキャッシュを利用しているため、多くの場合はこのフックを使わずに済みます）。
* `gpbpn_query_args`（filter）— `WP_Query` に渡す引数を変更します。`post_status` の拡張や Polylang/WPML 連携などに使用できます。`post_type` と `posts_per_page` の上限は内部で強制されます（厳密一致が有効なときは、完全一致を探すため件数の上限なしで候補を取ります）。
* `gpbpn_pattern_not_found`（action）— パターンが見つからないときに発火します。ロギング・監視用途に使用できます。
* `gpbpn_result`（filter）— 取得結果（`WP_Post|null`）を返す直前に加工・差し替えます。戻り値は `WP_Post|null` に丸められます。
* `gpbpn_duplicate_pattern_found`（action）— 同名の同期パターンが複数存在するときに発火します。監視・通知用途に使用できます。厳密一致が有効なときは、完全に一致するものが 2 件以上あるときだけ発火します。
* `gpbpn_max_name_length`（filter）— パターン名として受け付ける最大長（バイト数）を変更します。既定は 255 です。名前にだけ適用し、スラッグには適用しません。
* `gpbpn_strict_title_match`（filter）— `true` を返すと、取得した `post_title` が問い合わせ文字列と完全に一致する場合のみパターンを返します。DB の照合順序は大文字小文字や全角/半角を区別しない場合があるため、権限の低いユーザーが紛らわしい名前で作成したパターンに差し替えられるのを防げます。第 4 引数 `$caller`（`'name'` または `'name_or_slug'`）で呼び出し元を判別できます。`get_pattern_by_name()` の既定は `false`、`get_pattern_by_name_or_slug()` とブロックの既定は `true` です。
* `gpbpn_synced_only`（filter）— `true` を返すと、`wp_pattern_sync_status` メタが未設定または空の（完全に同期している）パターンのみを取得対象にします（既定 `false`）。

**REST ルート**

編集画面のサイドバーが使う `GET /wp-json/gpbpn/v1/resolve?value={名前またはスラッグ}` を提供します。ブロックの描画と同じ関数で解決した結果（`id`・`title`・`slug`・`matched_by`・`edit_url`・`conflict`）を返します。`edit_posts` 権限が必要で、見つからないときは 404 を返します。

使用例:

```php
// 厳密一致を、get_pattern_by_name() でも要求する.
add_filter( 'gpbpn_strict_title_match', '__return_true' );

// ブロックと get_pattern_by_name_or_slug() の厳密一致を、無効にする(第 4 引数で呼び出し元を判別する).
add_filter( 'gpbpn_strict_title_match', function ( $strict, $name, $field, $caller ) {
    return 'name_or_slug' === $caller ? false : $strict;
}, 10, 4 );

// 同期パターンのみを取得対象にする.
add_filter( 'gpbpn_synced_only', '__return_true' );

// post_status を拡張する（publish 以外を返す場合、閲覧権限の確認はプラグイン側で自動的に行われます）.
// 注意: wp_block は capability_type が独自の "block" のため、private 等を返す場合に
// 必要となる権限（read_private_blocks 相当）は既定では管理者ロールにも付与されていません。
// 付与されていない場合、この拡張は管理者であっても常に null を返します（安全側の挙動です）。
// 実際にこの拡張を使う場合は、対象ロールに add_cap() などで明示的に権限を付与してください.
add_filter( 'gpbpn_query_args', function ( $args ) {
    $args['post_status'] = array( 'publish', 'private' );
    return $args;
} );

// 見つからなかった場合にログを残す（本番環境では WP_DEBUG 時のみ、改行除去・長さ制限を行うこと）.
add_action( 'gpbpn_pattern_not_found', function ( $pattern_name ) {
    if ( ! WP_DEBUG ) {
        return;
    }
    $safe_name = substr( str_replace( array( "\r", "\n" ), ' ', $pattern_name ), 0, 200 );
    error_log( sprintf( 'Pattern not found: %s', $safe_name ) );
} );
```

== Installation ==

1. プラグインの ZIP ファイルをダウンロードします。
2. WordPress 管理画面の「プラグイン」→「新規追加」→「プラグインのアップロード」からインストールします。
3. プラグインを有効化します。
4. ブロックエディターで「パターン（名前またはスラッグ）」ブロックを挿入するか、テーマやカスタムコードから `get_pattern_by_name( $name )` などを呼び出します。

または、`get-patterns-by-pattern-name` フォルダを `/wp-content/plugins/` に直接アップロードし、管理画面から有効化してください。

WordPress 6.8 以上が必要です。

== Frequently Asked Questions ==

= 「名前」とは何ですか？ =

WordPress 管理画面の「パターン」（または「再利用ブロック」）一覧に表示されるタイトル（`post_title`）です。スラッグではありません。

= スラッグはどこで確認できますか？ =

管理画面の「パターン」画面や編集画面にはスラッグの表示欄がありません。「パターン（名前またはスラッグ）」ブロックを選択すると、サイドバーに「スラッグ:」が表示されます。REST の `/wp/v2/blocks` の応答にも `slug` が含まれます。

= ブロックに何も表示されません =

次を確認してください。編集画面のサイドバーで、指定した文字列が「見つかりません」になっていないか。パターンが公開済み（下書きや非公開でない）か。パスワードが設定されていないか。名前が違っていないか（大文字小文字や全角/半角の違いは、厳密一致のため一致しません。英字の大文字小文字だけなら、スラッグ側で一致することがあります）。名前を変更した後なら、作成時の名前（スラッグ）で指定し直してください。

= 本番でスラッグが `-2` になってしまいました =

同名のパターンが既にあると、WordPress がスラッグに `-2` などを付けます。名前で指定していれば、スラッグがずれても表示されます。スラッグで指定したい場合は、`wp post update {ID} --post_name={スラッグ}` で直すか、WXR で移行してください（上の「環境間の移行」を参照）。

= 同名のパターンが複数ある場合はどうなりますか？ =

投稿 ID が最も小さいもの（最初に作成されたパターン）を返します。重複が見つかると `gpbpn_duplicate_pattern_found` アクションが発火するため、監視・通知に利用できます。パターン名は一意にしておくことを推奨します。

= `gpbpn_query_args` で post_status に private 等を含めても null が返ってきます =

`wp_block` 投稿タイプは `capability_type` が独自の "block" であるため、非公開状態を読み取るための権限（`read_private_blocks` 相当）が既定では管理者ロールにも付与されていません。この権限が付与されていない環境では、`post_status` を非公開系に拡張しても、管理者を含め全てのユーザーに対して `null` が返ります（意図的な安全側の挙動で、セキュリティ上の問題ではありません）。実際にこの拡張を利用する場合は、対象ロールに `add_cap()` 等で該当の権限を明示的に付与してください。

= 非同期パターン（unsynced pattern）も取得されますか？ =

既定では、投稿タイプが `wp_block` であれば同期・非同期（`wp_pattern_sync_status` メタが `unsynced` のもの）を問わず取得します。同期パターンのみに限定したい場合は `gpbpn_synced_only` フィルタで `true` を返してください。ブロックの選択欄には、同期パターンだけが出ます。

= パターンが見つからない場合の戻り値は？ =

`null` を返します。呼び出し側で戻り値を必ず確認してください。

= 大文字小文字や全角/半角だけが違う名前でも一致してしまいます =

`post_title = %s` の比較は DB の照合順序（collation）に依存するため、WordPress 標準の照合順序では大文字小文字を区別せず、環境によっては全角/半角のかなの差も同一視されます。厳密な完全一致のみを許可したい場合は `gpbpn_strict_title_match` フィルタで `true` を返してください（`get_pattern_by_name_or_slug()` とブロックは既定で有効です）。

= 編集者はパターンを編集できますか？ =

できます。編集者ロールは、サイトエディター（`edit_theme_options` が必要）には入れませんが、`post.php?post={ID}&action=edit`（サイドバーの「このパターンを編集」リンク）でパターンを編集できます。

= キャッシュはどのように無効化されますか？ =

`save_post_wp_block` / `post_updated` / `trashed_post` / `untrashed_post` / `deleted_post` のいずれかが `wp_block` 投稿に対して発火すると、内部キャッシュのバージョン番号を進めることで一括無効化します（無関係な投稿タイプの保存では無効化されません）。データベースを直接操作するなど、これらのフックを経由しない変更を行った場合はキャッシュが更新されない点にご注意ください。

== Changelog ==

= 1.5.0 =
* 新規ブロック `gpbpn/pattern` を追加。テンプレート・テンプレートパーツ・投稿本文に置け、名前（見つからなければスラッグ）で同期パターンを引いて表示します。編集画面には、同期パターンの選択欄・プレビュー・サイドバー（名前・スラッグ・一致方法・編集リンク・スラッグ指定への切り替え）を備えます。日本語の翻訳を同梱。
* 新規関数 `get_pattern_by_slug()`（スラッグの完全一致）と `get_pattern_by_name_or_slug()`（名前を優先し、見つからなければスラッグ）を追加。`get_pattern_by_name()` の挙動は変わりません。
* 既存の 6 つのフック（`gpbpn_pre_get_pattern`・`gpbpn_query_args`・`gpbpn_synced_only`・`gpbpn_duplicate_pattern_found`・`gpbpn_pattern_not_found`・`gpbpn_result`）と `gpbpn_strict_title_match` の最後に、`$field` 引数を追加。`gpbpn_strict_title_match` には呼び出し元を表す第 4 引数 `$caller` も追加。
* `gpbpn_strict_title_match` を、`get_pattern_by_name_or_slug()` とブロックでは既定で有効に（`get_pattern_by_name()` は 1.4.0 までと同じく既定で無効）。
* 修正: `gpbpn_strict_title_match` を有効にしたとき、照合順序では同じ名前になる候補のうち ID の小さい 1 件だけを比べていたため、完全に一致するパターンが別にあっても null を返していた不具合を修正（`ABC` と `abc` があるとき `abc` を指定すると null になっていた）。重複検知も、完全に一致するものが 2 件以上あるときだけ発火するように修正。無効のとき（既定）の挙動は変わりません。
* 新規 REST ルート `GET /gpbpn/v1/resolve`（編集画面用）を追加。
* 動作要件を WordPress 6.8 以上に変更。WordPress 7.1.2 で動作確認済み。

= 1.4.0 =
* GitHub Releases を版元とした自動更新に対応。wp.org 未掲載のため `Update URI: false` を設定し、管理画面での更新通知・ワンクリック更新を独自に提供します。`l2dwpghul_updater_enabled` フィルタ（第 2 引数はプラグインスラッグ）で `false` を返すと、更新チェックの HTTP 通信を完全に無効化できます。
* WordPress 7.1 で動作確認済み。`Tested up to` を 7.1 に更新。

= 1.3.0 =
* パフォーマンス: 解決結果をオブジェクトキャッシュに保存するようにし、同じパターン名への繰り返しの呼び出しでクエリの再発行を回避。パターンの保存・更新・削除（`save_post_wp_block` / `post_updated` / `trashed_post` / `untrashed_post` / `deleted_post`）で自動的に無効化されます。見つからなかった結果も含めてキャッシュされ、`gpbpn_query_args` フィルタで変わりうるクエリ条件ごとに別のキャッシュとして扱われます。
* パフォーマンス: `WP_Query` を投稿 ID のみ取得する方式に変更し、投稿オブジェクト自体は `get_post()` 経由で WordPress コア標準の投稿オブジェクトキャッシュを活用するように変更。
* セキュリティ: 新規フィルタ `gpbpn_strict_title_match` を追加。`true` を返すと、DB の照合順序（大文字小文字・全角/半角を区別しない場合がある）に依存しない、厳密なタイトル完全一致のみを許可します（既定 `false`。後方互換のため opt-in）。
* 新規フィルタ `gpbpn_synced_only` を追加。`true` を返すと、`wp_pattern_sync_status` メタが未設定/空の同期パターンのみを取得対象にします（既定 `false`。後方互換のため opt-in）。
* テスト: PHPUnit + wp-env によるテストスイートを追加（入力検証、重複名の解決順序、各フィルタ・アクション、非公開投稿の権限チェック、キャッシュのヒット/無効化などを検証）。

= 1.2.0 =
* セキュリティ: 同名パターンが複数存在する場合、後から作成されたものが意図せず優先されないよう既定の並び順を ID 昇順に固定。重複は `gpbpn_duplicate_pattern_found` アクションで検知・通知できます。
* セキュリティ: `gpbpn_query_args` フィルタの戻り値を検証し、投稿タイプの固定・取得件数の上限化、および非公開投稿を返す場合の閲覧権限チェック（`current_user_can( 'read_post' )`）を追加。
* セキュリティ: `gpbpn_result` フィルタの戻り値を `WP_Post|null` に丸めるよう修正し、不正な値による fatal error を防止。
* セキュリティ: 入力値の検証を強化し、文字列以外や極端に長い入力を早期に拒否（新規フィルタ `gpbpn_max_name_length`、既定 255）。
* readme: `error_log()` のサンプルコードを、ログインジェクション対策（改行除去・長さ制限・`WP_DEBUG` 条件）を行った安全な形に修正。
* readme: 「最初に見つかった 1 件」という記述を「ID が最も小さい 1 件」に訂正し、非同期パターンも取得対象に含まれる既知の制限事項を明記。

= 1.1.0 =
* `gpbpn_pre_get_pattern`・`gpbpn_query_args`・`gpbpn_pattern_not_found`・`gpbpn_result` の 4 フックを追加。
* `get_pattern_by_name()` に `function_exists()` ガードを追加し、他プラグイン・テーマとの関数名衝突による fatal error を防止。

= 1.0.0 =
* 初回リリース。`get_pattern_by_name()` 関数を追加。

== Upgrade Notice ==

= 1.5.0 =
WordPress 6.8 以上が必要になります（6.0〜6.7 のサイトでは、1.5.0 は動作保証の対象外です）。`get_pattern_by_name()` の関数シグネチャ・戻り値・既定の挙動は後方互換です。既存のフックのコールバックは、スラッグで探すときにも呼ばれる点にご注意ください（第 2 引数がスラッグになります。最後の引数 `$field` で判別できます）。`gpbpn_strict_title_match` を有効にしていて、完全に一致するパターンが別にあるのに null が返っていた場合は、このバージョンで正しく返るようになります。

= 1.4.0 =
既存の関数シグネチャ・戻り値・既定の挙動は後方互換です。GitHub Releases を版元とした自動更新機構が新たに追加され、更新チェックのために api.github.com への外部 HTTP 通信が発生するようになる点にご注意ください（`l2dwpghul_updater_enabled` フィルタで無効化可能）。

= 1.3.0 =
既存の関数シグネチャ・戻り値・既定の挙動は後方互換です（新しいフィルタは全て既定 off）。内部キャッシュが追加されたため、データベースを直接操作するなど `save_post_wp_block` 等のフックを経由しない方法でパターンを変更している場合、変更が反映されるまでにキャッシュの無効化が必要になる点にご注意ください。

= 1.2.0 =
セキュリティ修正を含みますが、既存の関数シグネチャ・戻り値の型は後方互換です。`gpbpn_query_args` フィルタで `post_status` を拡張している場合、非公開投稿に対する閲覧権限チェックが新たに行われる点にご注意ください。

= 1.1.0 =
フック追加のみで既存の挙動に変更はありません。アップグレード作業は不要です。

= 1.0.0 =
初回リリースです。アップグレード作業は不要です。
